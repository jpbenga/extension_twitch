# CHANTIER A — CONSOLIDATION UX UNDERCOVER

## Contexte

L'application est fonctionnelle mais juxtapose encore plusieurs générations d'interface.

L'audit a notamment établi :

- le parcours Undercover principal fonctionne réellement ;
- plusieurs préparations peuvent déjà être enregistrées, ordonnées, dupliquées et réutilisées ;
- les images A/B existent réellement ;
- le nouveau Broadcast TV existe réellement ;
- le vocabulaire actuel `Série / Partie / Manche` crée une ambiguïté ;
- les réglages Broadcast avancés encombrent encore la préparation ;
- certaines sorties/navigation sont insuffisantes ;
- pause, fin anticipée et abandon n'existent pas encore fonctionnellement.

Nous voulons consolider l'UX sans détruire les capacités existantes.

---


Le mot `Cycle` est une hypothèse de vocabulaire.

Tu peux proposer une meilleure appellation si elle est immédiatement compréhensible.

NE PAS utiliser le même mot `manche` pour :

1. une paire Sasuke / Itachi ;
2. un nouveau cycle indices + vote avec la même paire.

La distinction doit être immédiatement compréhensible.

```text
[ IMAGE ITACHI ]

Participants
3

Tours d'indices
2

Options
>

[ Ajouter cette manche ]
```

Le CTA image doit clairement ressembler à UNE ACTION.

Éviter les liens ambigus tels que :

`Modifier les contenus`

si l'utilisateur ne comprend pas qu'ils sont cliquables.

Préférer selon le contexte :

`Ajouter une image`
`Choisir une image`
`Remplacer l'image`
`Modifier`

avec une vraie affordance de bouton.

# A6 — BROADCAST DANS LA PRÉPARATION

Le Broadcast TV moderne existe déjà.

NE LE REDESSINE PAS.

Le problème est son exposition.

La préparation normale ne doit plus être dominée par :

- le damier ;
- les coordonnées ;
- les sept blocs ;
- les presets techniques ;
- l'éditeur complet de disposition.

Créer une hiérarchie beaucoup plus simple.

Exemple :

```text
Diffusion

Habillage TV
[ Aperçu ]

Mode public
Duo anonyme ▾

Ajustements avancés >
```

`Ajustements avancés` peut conduire à l'éditeur existant.

Les 7 blocs et les dispositions personnalisées doivent être conservés.

Ils deviennent une capacité avancée, pas le cœur de la préparation.

# A9 — CYCLE DE VIE GM

Concevoir les états UX, SANS prétendre que le backend existe déjà.

Les capacités suivantes sont actuellement absentes fonctionnellement :

- mettre en pause ;
- reprendre ;
- terminer volontairement avant le résultat automatique ;
- terminer l'ensemble de la partie préparée ;
- abandonner / annuler.

Nous voulons explorer leur UX.

Différencier clairement :

## Mettre en pause

Action réversible.

L'expérience pourrait indiquer aux joueurs et au public :

`Partie en pause`

Le backend devra ultérieurement définir quelles commandes sont bloquées.

## Terminer la partie

Clôture volontaire.

Conserver l'historique disponible.

## Annuler / abandonner

Sortie exceptionnelle.

Ne pas la confondre avec :

`Réinitialiser le salon`

Créer des confirmations accessibles et sobres.

Ne définis pas de conséquences serveur non validées.

Documente les hypothèses qui devront être arbitrées avant intégration.

# CHANTIER B — MOTION SYSTEM UNDERCOVER TV

Le renderer TV léger existant est conservé.

Nous voulons maintenant définir son langage d'animation.

Principe :

> La vidéo est le contenu principal.
> L'overlay est une surcouche télévisuelle discrète.

Les animations doivent rester :

- courtes ;
- lisibles ;
- élégantes ;
- contextuelles ;
- jamais envahissantes ;
- compatibles avec Twitch mobile ;
- compatibles `prefers-reduced-motion`.

---

# B1 — NIVEAU 1 : MICRO-ANIMATIONS

Explorer :

- glow léger sur joueur actif ;
- pulsation discrète d'un état actif ;
- apparition douce d'un badge ;
- compteur de votes avec transition légère ;
- changement de texte sans saut visuel.

Éviter :

- bounce excessif ;
- shake ;
- néons permanents agressifs ;
- clignotements.

---

# B2 — NIVEAU 2 : TRANSITIONS D'ÉTAT

Documenter entrée et sortie pour :

- attente → discussion ;
- joueur actif suivant ;
- discussion → vote ;
- vote → résultat ;
- résultat → nouveau cycle ;
- fin d'une manche → manche suivante.

Exemple :

```text
Discussion
fade / slide léger

↓

Vote
ancien badge sort
nouveau badge entre
```

---

# B3 — NIVEAU 3 : MOMENTS TV

Moments plus expressifs mais rares :

- Duo anonyme ;
- égalité ;
- élimination ;
- révélation finale ;
- victoire ;
- transition vers la manche suivante.

Exemple Duo :

```text
carte A entre doucement à gauche
carte B entre doucement à droite

VS apparaît

2–3 secondes

l'ensemble se réduit vers son état compact
```

---

# B4 — DUO ANONYME

Conserver strictement la confidentialité.

Afficher :

- les deux contenus ;
- leurs images.

Ne jamais révéler l'affectation des joueurs.

Définir :

- apparition ;
- durée ;
- retrait ;
- état compact éventuel.

---

# B5 — AFFECTATIONS VISIBLES

Animation des cartes joueur → contenu.

Prévoir :

- 3 joueurs ;
- 6 joueurs ;
- 12 joueurs.

Ne pas simplement réduire 12 cartes identiques jusqu'à devenir illisibles.

Respecter la pagination / logique compacte existante.

---

# B6 — VOTE

Explorer :

- ouverture du vote ;
- votes reçus ;
- progression ;
- clôture.

Le vote ne doit jamais recouvrir inutilement les visages.

---

# B7 — ÉLIMINATION

Moment TV court.

Exemples possibles :

- carte isolée ;
- baisse d'opacité des autres ;
- ligne accentuée ;
- sortie douce.

Pas d'effet agressif.

---

# B8 — ÉGALITÉ

État exceptionnel clairement identifiable mais bref.

---

# B9 — RÉVÉLATION / VICTOIRE

Le moment le plus expressif.

Mais rester cohérent avec une production TV premium.

Une animation de révélation peut être plus forte, puis laisser place à un état final durable.

Important :

l'ouverture tardive d'un overlay ne doit pas forcément rejouer une animation historique.

Concevoir séparément :

`transition événementielle`

et :

`état durable après événement`.

---

# B10 — MANCHE SUIVANTE

Créer une transition courte.

Exemple :

```text
Manche suivante

Messi
VS
Ronaldo
```

puis retour vers le HUD minimal.
